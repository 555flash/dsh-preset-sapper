# 接力 — 你会被压缩，会被换掉

对话会被压缩，子代理会死，会话会换人。**只有两样东西能活下来：`.sapper/` 里的图，和 `commander-state.md`。**
本条的全部目的：让「下一个你」在 60 秒内接管，而不是从零重新推导战略。

## 一、战役目录结构

```
<战役目录>/                     ← 会话工作目录必须落在这里
├── .sapper/                    ← 事实图（工具读写，不要手改）
├── commander-state.md          ← 你的接力卡（只有 COMMANDER 写）
├── AGENTS.md                   ← 章程：目标、授权边界、红线（可被自动加载）
├── raw/                        ← 原始输出，按 worker 分片
│   ├── scout-a/
│   ├── soldier-b/
│   └── sensors/                ← 传感器原始返回（JSON/截图）
├── cases/                      ← 案例卡：一个问题一张
├── artifacts/                  ← 交付物：报告、指纹表、PoC、图
└── STALLED.md                  ← 只在真的挂起时写
```

**工作目录 = 图的位置**。在别处开会话，看到的是另一张空图，`session_search` 也检索不到这场战役（它只检索 cwd 完全一致的历史会话）。

## 二、`commander-state.md` 模板（≤150 行，表格化，不许散文）

```markdown
ITERATIONS: 17
目标: <终态一句话>
章程: AGENTS.md（授权边界见 §范围）
预算: <截止时间/轮次>      槽: 5/8 在跑   smart: 2/3

## 分配
| 目标 | 状态 | worker | 模型 | 下一步 | 备注 |
|---|---|---|---|---|---|
| web-01 | attacking | scout-a | flash | 派 soldier 打 LFI | 已确认 nginx 1.24 + LFI |
| api-03 | parked | — | — | 缺一个可用凭据 | 40 分钟无入口 |

## 停放（无新情报不重开）
- api-03: 试过 admin/admin、/api/v1/debug（404）、目录爆破前 2000 条无果

## 情报日志（已确认、可迁移）
- e-系列 WAF 绕过：`<payload 原文>`
- 同族目标共享 `/download?file=` 路径穿越

## 队列（按易者先行）
- web-05, web-07

## 关键事实索引（图里已有，别重复查）
- f001 443 nginx 1.24.0 · f004 LFI 可读 /etc/passwd · f009 admin 凭据

## NEXT
1. 派 soldier-c（flash）读 nginx.conf 找凭据面，20 分钟盒
2. 若拿到凭据 → web-05 同族复用
```

**写 STATE 的时机**（不是"想起来才写"）：
- 每轮 `ITERATIONS` +1；
- 任何大决定之后（派单、停放、重开、换路线）；
- 上下文压力到 85%——**立刻停手重写**，再谈别的。

## 三、压缩协议

DSH 的自动压缩由 `compaction-basic` 处理（另有 `/compact` 命令可手动触发）。你无法控制它何时发生，只能控制**它发生时你在哪**：

1. **~85%**（信号：上下文告警、ITERATIONS 到 8、你发现自己记不清三条事实的 id）：
   **停止一切调查动作**，只做一件事——把 STATE 重写到"陌生人能接管"的程度。分配表、停放原因、情报日志、队列、NEXT，一个都不能缺。
2. **压缩发生**：不要试图回忆，也不要重新开场。
3. **压缩后第一个动作**：`read commander-state.md`。
4. **第二个动作**：`sapper_state action=status`（以图为真，STATE 与图冲突时信图）。
5. **第三个动作**：从 STATE 的 `NEXT` 第一项直接执行。

**不许做的事**：压缩后重新问用户"我们要做什么"；重新扫一遍已经确认的目标；把已经收口的 intent 再开一遍（`sapper_state action=frontier` 会告诉你哪些是真就绪）。

## 四、新会话接班（人或另一个 agent 开的新会话）

按顺序，别跳：

1. `sapper_state action=status` → 有没有图？终态是什么？frontier 里有什么？
2. `read AGENTS.md` → 授权边界与红线（这个永远优先于任何战术冲动）。
3. `read commander-state.md` → 上一任留下的 NEXT 与停放原因。
4. `sapper_state action=recall query="<你要做的事>"` → 这件事是不是已经做过？
5. `sapper_state action=validate` → 图有没有被写坏。
6. 然后才读 `SKILL` 里的具体打法。

**接班的纪律**：不推翻前任的战略，除非你带来了**新情报**。推翻要写明"为什么前任的判断不成立"，并作为一条 `note` 入图。

## 五、跨子代理交接

子代理不继承你的上下文（`subagent_fork` 除外）。所以派单必须自带：

- 目标与终态；
- 图里最关键的 3–5 条事实（带 id）；
- 范围与红线；
- 产出格式（事实 + 8 行卡）；
- 时间盒。

**不要**让子代理"先去读图了解情况"——它会把整张图读进上下文，然后忘掉你真正要它做的事。**你替它读，你给它结论。**

## 六、案例卡（一个问题一张）

`cases/<日期>-<目标>-<一句话>.md`：

```markdown
# <标题>
场景：<什么条件下遇到的>
输入：<请求/参数/文件>
反应：<状态码/回显/报错，原文>
判定：<已确认的结论 + 级别 HARD/SOFT/UNTESTED>
可复用：<下次遇到同类直接抄什么>
关联：f004, i007
```

案例卡是给**下一场战役**用的，不是给本案报告用的。写法以"三个月后的自己能看懂"为准。

## 七、交付物清单（收口时逐项打勾）

- [ ] `sapper_state action=validate` 通过（无断链、无孤儿事实）
- [ ] 每条关键结论都有对应 fact，且 `data` 里有精确值
- [ ] 阴性结论都带三问证据（协议/出口/姿势），否则标 `UNTESTED`
- [ ] 归因结论都标了 `HARD` / `SOFT`
- [ ] `raw/` 里的原始件与事实里的 `f` 编号能对上（可复核）
- [ ] 报告里每个数字都能追到一条事实或一个原始文件
- [ ] 不把含个人信息的原始件放进交付物；敏感结论用最小断言
- [ ] `commander-state.md` 的 NEXT 清空，或写明"已挂起，原因 X"
- [ ] `sapper_write action=complete from=[...] text="<收口说明>"` 挂上终态边

## 八、挂起（真的打不动时）

只在**同一阻塞连续 3 轮**、且已试过换参数/换出口/换姿势之后：

```
sapper_write action=note text="STALLED: <阻塞点>｜已试：<证据>｜选项：<3 个>｜默认：<动作>"
```

然后写给人的阻塞卡：**阻塞点 + 已试证据 + 3 个可选项 + 默认动作**。
不要用"我卡住了"当结论，也不要用 `ask_user_question` 问"下一步做什么"——写成选项让人选，或按默认动作继续（红线除外）。
